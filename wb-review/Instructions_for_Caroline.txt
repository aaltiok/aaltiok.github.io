WORLD BANK DOCUMENT CLASSIFICATION REVIEW

There are two ways to review the same data. Use whichever is easier.

OPTION 1 — THE INTERACTIVE FILE
1. Open World_Bank_Review.html in your usual browser. No installation, website account or internet connection is required for the review itself.
2. Enter your name. Names identify proposals; they are not verified accounts.
3. Start in Explore metadata. “Retained corpus” shows the 13,271 documents currently used in the analysis. “All original records” shows the 41,286 records before cleaning. “Excluded records” includes every cleaning reason, not just excluded document types.
4. Group by the Bank’s document type or product line. Open a group to inspect its overlap with the other classification and read example titles. Original Bank source links can be opened when online.
5. Save your proposal for Script/Practice or for a knowledge-product grouping. You can separately propose Include or Exclude. “No change” preserves the existing baseline; “Unresolved” records an undecided classification. Use an individual exception when a group rule does not fit a particular document.
6. Compare approaches shows the effect on counts. Conflicting document-type and product-line rules appear as “Needs review”; individual exceptions override group rules. Use “Agreed decision” only after discussion, not for an independent first review.
7. Click Export JSON and send the downloaded file back to Ali. Your changes are saved in this browser, but are NOT automatically shared or backed up. Export before changing computers, browsers, file locations or clearing browser data. The JSON export is the transferable copy of your work.
8. Import reviews loads a returned JSON file. Use it to bring your work to another browser or to inspect proposals from another reviewer. The original metadata stays unchanged.

OPTION 2 — EXCEL
1. Open World_Bank_Classification_Review.xlsx.
2. “Document types” lists the 126 types marked Keep in the current type-selection rules, including types with zero documents surviving cleaning. “Excluded types” lists all 53 types marked Exclude. Counts distinguish the original collection from the retained analysis.
3. Fill only the Caroline columns. Leave a cell blank to propose no change. Script/Practice and Include/Exclude are separate decisions. Use “Discuss” where the distinction needs agreement.
4. “Bank product lines” shows the ORIGINAL product-line labels recovered from the World Bank API. You may propose a function and a knowledge grouping separately. Multiple product lines can apply to one document, so row counts can overlap.
5. “Individual review” contains the 184 retained records originally missing a document type. Add a row with the document ID if a further individual exception is needed. All_documents.csv provides a searchable list of all 41,286 source records and their cleaning status.
6. Save the workbook with your name in the filename and send it back to Ali. Ali can convert the completed review into JSON; you do not need to edit JSON or run any code.

WHAT THE LABELS MEAN
Document type, major document type, product line and collection are World Bank metadata. Current Script/Practice codes and cleaning decisions belong to this research project.
The spreadsheet’s first column uses the Bank’s major document categories. It does not use the project-created “document families.”
Product lines describe associated Bank activities. A Working Paper can, for example, be associated with Technical Assistance. A product line is not the same thing as a publication format.
Missing product-line metadata does not mean noncore knowledge. “Core-related” is a proposed analytical grouping, not a certification that all conditions in the 2011 report were met. The initial comparison keeps ASA, other lines and missing labels visible separately.
Document dates do not tell us when a product-line label was assigned. The corpus covers 1990–2025 and the administrative terminology changed during that period.

No choice in these files changes the source corpus or reruns any topic model.
